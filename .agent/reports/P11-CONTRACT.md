## 1. Scope and non-goals

P11 wires the already-accepted P10 `teyru-lsp` stdio server into IntelliJ IDEA Ultimate as a real, packaged plugin using the platform's built-in LSP client (`com.intellij.platform.lsp.api`), pinned to the exact IDE build P01 already probed: **IU 2026.1.4, product build 261.26222.65** (`since-build=261`, `until-build=261.*`). The plugin is real: a `plugin.xml` descriptor, a `LspServerSupportProvider` that launches the actual `teyru-lsp` distribution built by P10, and file-type registration for `.teyru`. It is verified by running the pinned JetBrains Plugin Verifier against the real packaged plugin ZIP and the real pinned IDE build — not a fabricated/empty plugin, and not a documentation-only claim.

P11 does not claim: marketplace publication, support for any other IDE product/build range, a custom language grammar/PSI (`.teyru` files are treated as plain-text/LSP-driven, no `ParserDefinition`), a debugger, refactoring support, or an in-process editor smoke test with a rendered UI (IntelliJ's UI test framework requires a display and remains out of scope; verification is headless: Plugin Verifier plus a headless application-level test using `IntelliJ Platform Test Framework`'s light fixture, which loads the plugin and platform services without a window server).

The described best-effort read-and-forward of `build/teyru/workspace/main.json` is entirely absent from the code.

This is a gap against the frozen contract's own section 3, independent of the P11-01..P11-07 acceptance-matrix wording, and the self-reported implementation summary at the top of this file overstates what was built (it claims the initializationOptions wiring as done; it is not).
