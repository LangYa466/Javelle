## 1. Starting point

`compiler-core/src/main/java/dev/teyru/compiler/core/frontend/StatefulTeyruLexer.java` is the P05 minimal lexer (322 lines): identifiers/keywords (18-word list), a numeric-literal scanner that already handles decimal/hex/binary/octal-by-underscore, underscores, hex-float, exponents and suffixes, single/double-quoted literals with naive backslash-skip (no escape validation), `//` and `/* */` comments with no Javadoc distinction, whitespace/newline trivia, and a greedy multi-character operator table. Text blocks are explicitly rejected as `TY-DEV-0001 "text blocks unsupported at P05"`. `>>`/`>>>` are always lexed as single multi-char operators (no generic-close splitting). There is no fuzz harness.

Two non-blocking gaps are recorded for a future round rather than blocking acceptance, since neither is contradicted by any passing test and neither represents a live crash/hang/regression risk found in practice:
1. A lone unpaired UTF-16 surrogate that reaches the lexer via Unicode-escape translation (not via malformed UTF-8, which is already handled) produces no diagnostic (P12-04). If a future change to the lexer introduces a loop that isn't provably bounded, this harness would hang rather than fail cleanly. Recommend wrapping the fuzz loop in a real per-trial timeout (e.g. `assertTimeoutPreemptively`) in the next round that touches this file.
